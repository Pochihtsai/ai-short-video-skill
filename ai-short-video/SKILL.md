# 中英文短片，直式與橫式（HyperFrames）

先讀 `/hyperframes` skill 的 SKILL.md，只要看「Contract」那 12 條規則，本檔只補 HyperFrames 沒寫的規則。它的工作流程（`story.md`、`SPEC.md`、`snapshot --review` 與 `REVIEW.md`、輸出前開預覽、查使用量、每一幕拆成子組合檔）由本檔的五關和「自檢」取代，不必照做，也不必讀那些文件；使用者要求時才開預覽（它寫「沒人問也要開預覽」，這點以本檔為準）。用到 3D 或 canvas 時，再讀它的 `references/runtimes.md` 和 `references/types/3d.md`。**走輕量模式時連 Contract 都不必讀**：`index.html` 由 `quick_build.py` 產生，不手寫動畫。目的：省下讀文件和規劃的時間（2026-11-22 量測：讀 skill、規劃佔一支片 2–6 分鐘）。工作資料夾放在 `~/Desktop/Claude/影片/<片名>/`。

## 工具（裝好的位置）

- HyperFrames：用 `npx hyperframes`；它的 skill 都在 `~/.claude/skills/`
- FFmpeg、Node.js 22 以上、Google Chrome
- 配音用的 edge-tts（中英文都用它），裝在獨立環境裡：
  - Mac：`~/.venvs/edge-tts/bin/python`
  - Windows：`%USERPROFILE%\.venvs\edge-tts\Scripts\python.exe`
- 音效庫：`~/.claude/skills/media-use/audio/assets/sfx/`，19 個，Pixabay 授權，免標示
- 配樂：不附音樂檔，每次依內容用 `scripts/find_music.py` 到 Mixkit、Openverse 找（見「聲音」）
- 人物：Open Peeps 手繪人物零件在 `references/peeps/`（CC0），用 `scripts/peep.py` 組（見「人物」）
- 本 skill 的腳本在 `scripts/`，Mac、Windows 都能跑（Mac 用 `python3`，Windows 用 `python`）

任何一項找不到，先照本 skill 資料夾裡的 `SETUP_給Claude的設定指引.md` 補裝；那份檔案不在的話，告訴使用者缺什麼，不要自己猜著裝。

## 流程：五關確認，全部通過才製作

目的：做一支片要跑好幾分鐘、花不少額度，方向越早對齊越不會整支重做。每一關只問一件事、附上推薦和理由，讓使用者看一眼就能決定。

| 關卡 | 交給使用者 | 存檔 |
|---|---|---|
| 0. 需求 | 一次問完：語言、直式或橫式、長度（建議 15、30 或 60 秒）、用途和觀眾。已經說了的不再問 | — |
| 1. 故事線 | 三條故事線，每條三到四句：切入角度、核心比喻、結尾想讓觀眾記住什麼。推薦一條並說理由。三條各代表一種做法（輕量模板、基本款、進階款，只列跟題目相符的），每條標出做法和大約要等多久，使用者挑故事時就一起決定做法（見下方「讓使用者選做法」）。另附一行：這支片屬於哪一類題目 | `01_故事線.md` |
| 2. 大綱 | 選定故事線的分幕表：每一幕幾秒、畫面大概是什麼、用哪一種排法、鏡頭（景別和怎麼動；只開基本款時寫「固定」或一個簡單的推近、拉遠就好）、要傳達的重點。最後一幕固定是結尾（見下方「結尾」）。開了導演原則進階款時，附一行參考作品：學它什麼、不拿什麼（見「導演原則」） | `02_大綱.md` |
| 3. 風格與配樂 | 用大綱裡最有代表性的一幕，做 **3 張**不同風格的靜態畫面：一張依內容推薦，另外兩張各換一種畫法（見下方「風格圖」），不能只換明暗。同時建議配樂方向，附 2–3 首候選曲的試聽和授權說明。每張風格圖附一行「設計判讀」（見下方「設計品味與動態」）。另外替 2–4 個關鍵動作各列 3 個動態效果（名稱、一句說明、示範連結），讓使用者點開看會動的示範再選。題目真的需要立體時，其中一張改成 3D，各標大約要等多久（見「3D 與 canvas」） | `03_風格/`（圖片）、`03_配樂.md`、`03_動態.md` |
| 4. 旁白稿 | 完整旁白，標出每一幕對應哪幾句，附字數和預估秒數，再附一段約 10 秒的配音試聽。停頓依第 1 關的題目類型：只開基本款時，中間不留停頓，只有結尾停住 | `04_旁白稿.md`、試聽檔 |
| 5. 製作 | 配音、動畫、字幕、音樂、音效一次做完，交第一版 | `renders/` |

規則：
1. **每一關都要等使用者確認才往下走**，沒確認之前不做下一關，更不能直接開始製作
2. 使用者說「後面照你的建議直接做」時，才可以略過剩下的關卡直接製作，並在製作前列出每一關採用的選擇。這時沒有人看中間產物，只做製作用得到的東西（2026-11-22 量測：前四關佔一支片 4–9 分鐘，其中不少是沒人看的對照和試聽）：
   - 各關檔案照樣存（中斷後接著做要用），但只寫選定的那一個方案加一行理由，不寫沒選的候選
   - 風格圖只做選定的一張，用來確認畫面長相；不做對照用的其他張
   - 配樂直接挑一首下載、剪好長度，不剪試聽檔；動態效果直接選定寫進 `03_動態.md`，不列候選
   - 不做配音試聽，直接產生正式配音
3. 回頭改前面的關卡時，只重做受影響的部分，例如改了某一幕的大綱，就只改那一幕的旁白，不從頭來
4. 每一關的檔案都存在影片資料夾裡，中斷後或使用者換新對話說「接著做 <片名>」時，先讀這些檔案接著做。不用主動叫使用者開新對話
5. 使用者丟參考圖片時，第 3 關就照那個方向做，不必再另外提其他風格

各關的做法：
- **需求**：沒說方向時，發到 Reels、Shorts、TikTok 用直式，發到 YouTube 或放進簡報用橫式
- **讓使用者選做法**：目的是讓使用者看得到差別時才做決定，不要在資訊還不夠時就要使用者選（2026-11-23 使用者指出）。第 0 關只問需求，不問走哪一款
  1. **第 1 關**：三條故事線各代表一種做法，只列跟題目相符的（題目類型見「依題目選原則」）：
     - 觀念溝通、字或符號當主角：內容放得進模板時，一條是輕量模板（每個重點演一幕，附 `references/quick/場景模板_場景範例.jpg` 給使用者看，並用一句話附上推薦的模板、風格、配樂，選了這條就一起確認，不再多問一次），其他是基本款；題目有角色可以演時，可以多列一條進階款
     - 實體操作、有角色的故事：至少一條基本款、一條進階款，推薦進階款；不列輕量模板
     - 使用者喜歡某條故事，就願意為它多等，所以每條都要寫出那條故事好在哪裡，不要只寫做法的名稱
  2. **第 3 關**：要不要用 3D 看風格圖決定，見「3D 與 canvas」
  3. **只講要等多久，不講費用或額度**：費用和額度依使用者用的模型和方案而不同，Claude 估不準（2026-11-23 使用者決定）。下表是全新分身照建議直接做、含自檢的實測（Opus 5.5，各只跑一兩次），寫成範圍給使用者看：

     | 做法 | 大約要等多久 |
     |---|---|
     | 輕量模板 | 5–10 分鐘 |
     | 基本款 | 15–20 分鐘 |
     | 進階款 | 25–30 分鐘 |
     | 進階款加 3D | 約 1 小時 |
  4. 選了輕量模板那條，改走「輕量模式」的流程；使用者說「照建議直接做」時，做法也由 Claude 決定，製作前列出採用的做法和理由
- **故事線、大綱**：
  1. 台詞長度：中文配音的速度看句子長短，句子長、標點少約每秒 4.5 字，短句多、標點多約每秒 3.8 字（2026-11-22 兩支驗證片：123 字配音 27.0 秒；108 字配音 28.6 秒）。30 秒的片先寫 110 字左右，配音後量實際長度再增刪，結尾要留 2–3 秒停住和淡出；英文約每秒 3 個字（30 秒約 90 個字，依 Andrew 18 字樣本估計，第一支完整片後再校正）
  2. **每個重點都要講得完**：一支 30 秒的片大約放 4–5 個重點（含結尾），每個重點至少約 5 秒，讓動畫做完、觀眾看懂。想講的比這多，就刪重點，不要每段縮短（2026-11-22 示範 1：5 幕的版本比 7 幕的清楚，使用者選了 5 幕那支）
  3. 前後相關的步驟（例如「拆工作」接「同時做」）盡量在同一個畫面裡往上加，不要切成兩幕；切開時中間容易出現空白，因果也會斷掉
- **結尾**：目的是讓觀眾感覺「講完了」，並帶走一句話。2026-11-21 使用者指出三支示範片都沒有結尾感：最後一幕停住後直接切掉，AI agent 片的最後一幕還標著「STEP 06」，看起來像第六步而不是結尾
  1. 大綱固定有最後一幕「結尾」，長度看結尾句和收尾動作需要多久，不放新資訊。結尾那句要是完整的一句話，只看結尾的人也看得懂，二選一：**鼓勵行動**（要做什麼＋做了會得到什麼）或**總結**（這支片講的事帶來什麼改變）。不要只重複片中的動作口號：2026-11-22 使用者指出「開會之前，先寫一頁」沒頭沒尾，改成「下次開會前，花五分鐘寫一頁議程，會議就能準時收尾」這種有好處的句子。第 4 關旁白稿要標出結尾那句
  2. 結尾畫面要看得出和內容不同：拿掉步驟編號、進度清單這類「還在進行中」的元素，換成收尾的版面，例如大字核心句、整個畫面拉遠看到全貌
  3. 要有一個「收」的動作，例如元素歸位、畫面拉遠、全部亮起後靜止；可以在第 3 關一起挑動態效果
  4. 旁白講完後，讓畫面停住一下再淡到底色，淡出和音樂的淡出一起結束（`prep_music.py` 讓音樂在最後 2 秒淡出），不要停在滿版畫面直接切掉
  5. 結尾大字和字幕內容重複時，保留大字，拿掉和大字重複的那幾組字幕（通常是最後一兩組）：先從 `captions.json` 刪掉，再跑 `captions_html.py`（三支示範片都遇到兩者重複）
- **風格圖**：「設計判讀」那一行寫在 `03_風格/說明.md`。在 `03_風格/<風格名>/` 各放一個只有那一幕、不配音的 `index.html`（版面照下方「語言與方向」），用 `npx hyperframes snapshot --at <秒數>` 截圖給使用者看。三種風格都由 Claude 依內容設計，沒有預設風格；使用者要「公司風格」時，參考 `references/design-glass.md` 的淺色玻璃風。圖要用跟成品同一套工具做，使用者看到什麼，成品就長什麼樣子
  - **三張要換畫法，不能只換明暗**：畫法指怎麼把內容畫出來，例如插畫、線稿圖解、紙張拼貼、字體排版當主角、照片感、3D。明暗和配色可以跟著變，但不能是唯一的差別。目的：讓使用者比較的是表達方式，不只是顏色（2026-11-23 回頭看 12 組風格圖，有 10 組只是「淺色一張、深色一張」，使用者指出）
  - 每張附一句「這種畫法適合這支片的什麼地方」，寫在 `03_風格/說明.md`
  - 選定的那張在 `03_風格/說明.md` 補成製作時照著做的規格，目的是每一幕都長得像同一支片、換新對話也接得下去。至少說清楚：風格名字、主色和輔色的色值、字型和用哪兩種粗細、動起來的個性、換場方式、畫面鬆緊，以及兩三件這支片不要做的事。寫法不限
- **動態效果**：目的是讓動作有名字可以溝通、選了就能照著做，又不多花額度。效果來自 Motion Prompt（MIT 授權、可商用的動態效果目錄，240 個效果，每個都有會動的示範）
  1. 從大綱挑 2–4 個關鍵動作，例如數字出現、清單依序進場、圖表長出來、換場，用 `scripts/motion_catalog.py search <英文關鍵字>` 各找 3 個候選。只把搜尋結果的名稱、一句說明、示範連結給使用者，不要把整份目錄讀進對話
  2. 使用者點連結看示範後選定，把編號和用在哪一幕寫進 `03_動態.md`
  3. 不必每個動作都挑。使用者說「動態你決定」時，由 Claude 選並寫進檔案
  4. 它管的是「怎麼動」，配色、字型、版面仍由風格圖決定
- **配樂**：照下方「聲音」的做法依內容找。第 3 關要附試聽，所以候選曲先下載到 `assets/bgm/candidates/` 各剪一段試聽；使用者選定後只把那一首剪成影片長度。「直接做」時只下載選定的一首。**不要叫使用者自己去網站下載**
- **旁白稿與試聽**：用 `scripts/tts_words.py` 產生試聽；換聲音之前先給試聽。台詞會送到微軟的線上服務，內容敏感時先告訴使用者
- **製作**：
  1. 配音：`scripts/tts_words.py` 同時產生 `voice.mp3` 和 `words.json`（逐詞時間）
  2. 動畫：用 `words.json` 決定每一幕的起訖時間和每個元素出現的時間點。寫法參考 `templates/`：直式看 `example_A_v3.html`，橫式看 `example_landscape_en.html`。範本只示範寫法（字型、時間軸、字幕迴圈、音軌、鏡頭、影片片段、結尾），裡面的方塊、六角形、佔位字都不是內容，不要沿用；故事、畫面和風格照前幾關的決定。2026-11-22 示範 1 的教訓：舊的直式範本本身是一支「AI agent 分工」的片，題目相同時兩個分身照著它的段落和畫面做，所以範本改成沒有故事的寫法示範。`03_動態.md` 有選效果的，用 `scripts/motion_catalog.py get <編號>` 讀規格（不加 `--code`），照規格裡的時間點和緩動曲線用 GSAP 改寫成本片的風格；不要直接貼它的 canvas 程式碼，那段程式碼自帶深藍配色和循環節奏（2026-11-19 實測：直接貼能輸出，但和成品風格不搭；照規格改寫的版本融入得很好）。在 HTML 註解寫上 `Motion Prompt #編號 · MIT © 2026 Shohei Ohtaki`
     - 橫式範本只示範左右構圖；結尾、鏡頭推近、影片片段的寫法看直式範本，橫式照樣適用
     - 節錄影片片段：`<video>` 放在最外層，自己帶 `data-start`、`data-duration`、`data-track-index`，加 `muted`；不能放進有時間設定的容器，外框和標籤另外畫在上面（寫法見直式範本的註解）
     - 打字效果（#006 Typewriter）：每個字先設透明時，字仍佔位置，游標會卡在整句最後面；改成每個字後面各放一個游標、依序切換
  3. 字幕：用 `scripts/make_captions.py` 切，不要自己用 `words.json` 拼（會掉中英文之間的空格、在怪地方斷句）；再用 `scripts/captions_html.py captions.json index.html [最後一組延長到第幾秒]` 放進 `index.html`。templates 的字幕區已經有 `<!-- captions:begin -->`、`<!-- captions:end -->` 兩行標記和字幕迴圈，不要手寫字幕的 div 和 tl.set
  4. 第一版就配好音樂和音效，不交無聲版。配樂用 `scripts/prep_music.py` 剪長度、統一響度；**輸出影片前**用 `scripts/music_volume.py` 算出 `data-volume`，不要輸出後才發現太大聲再重新輸出
  5. 自檢後輸出，見下方「自檢」。音樂要標示作者時，把說明欄要貼的標示文字一起交給使用者
- 做完把這次新確定的規則補進本檔

## 輕量模式

目的：觀念、口訣這類題目不一定需要從頭設計。改成「Claude 只寫內容，`scripts/quick_build.py` 套固定模板組片」，省掉規劃時的思考和反覆修改，換取明顯較短的時間和較少的費用。代價是版面、動態、音樂都從固定選項挑，用同一套模板做的片會彼此很像。

什麼時候用：
- 題目是「觀念溝通」或「字或符號當主角」（見下方「依題目選原則」），而且內容放得進模板：場景 3–5 個（橫式 6 個）、重點往上疊 3–5 個、大字主角 3–6 個
- 在第 1 關當其中一條故事線提出（見「讓使用者選做法」），使用者選了那條才用。那條要寫清楚代價：版面、動態、音樂從固定選項挑，片子會和其他輕量版很像
- 實測（2026-11-23，全新分身照建議直接做、含自檢）：5W1H 橫式 5.6 分鐘、US$1.0–1.3；AI 分工直式 4.4 分鐘、US$0.8–1.0；加上圖示和舞台版面後，新題目「問 AI 的 4 個技巧」橫式 5.8 分鐘、US$1.0–1.3，腳本一次就過、check 一次 ok。同題目一般流程（2026-11-22）是 16.6–28.6 分鐘、US$3.0–5.4。改成場景模板後（2026-11-23 試做E，同題目橫式）7.1 分鐘、US$1.1–1.4，其中輸出加 check 約 4 分鐘。各只跑一次
- 實體操作、角色故事，或內容放不進模板時，走一般流程，不要硬塞

固定選項（選了輕量模板的故事線後一次選完，縮圖在 `references/quick/`，直接給使用者看，不另外截圖）：
- 模板：
  - `scene` 場景（預設推薦）：每個重點一幕畫面，有固定主角（六角形笑臉角色，一般的是白底、帶頭的是主色、負責檢查的是藍色）。開場是大標題加主角，講第一個重點時標題縮成頁首、旁邊小圓點標進度，結尾是帶頭的主角加結尾句。2026-11-23 加的：使用者看過舊模板覺得太陽春，原因是整支片只有一種構圖、每一幕只換一個圖示
  - 其他兩種：`stack` 重點往上疊（觀念、做法；講到哪個重點，那個重點的大圖示和那句字站上舞台，講下一個時縮小飛進旁邊的清單）、`big` 大字主角（口訣、縮寫、清單；大字旁邊配圖示和說明）。縮圖 `模板二選一_重點往上疊_大字主角.jpg`
- 場景（`scene` 模板每個重點都要填，欄位和字數上限寫在 `quick_build.py` 開頭說明的最後一段）：照那個重點在講什麼挑，讓畫面演出情境，不要只放一個代表概念的符號
  - `tree` 分工樹：一個帶頭的分給 2–4 個。分工、拆解、組織
  - `split` 錯的 vs 對的：左邊打叉、右邊打勾。對照、常見錯誤、改善前後
  - `card` 清單卡逐項打勾：交代、檢查表、步驟裡的幾個要素。清單項可以各配一個 cue，講到時才打勾
  - `check` 驗收蓋章：做的人交出幾份成果，檢查的人逐張蓋勾或叉。驗收、把關、審查
  - `actor` 主角＋道具，可加一句對白泡泡。提醒、情緒、單一動作
  - `number` 大數字或大字，純數字會從 0 跳上去。數據、口訣裡的關鍵字
  - `icon` 大圖示。上面都不合適時才用
  - 同一支片盡量不重複；3–5 個重點至少用 3 種場景
  - 排法由腳本換：相鄰兩幕不會一樣（橫式左文右圖、右文左圖、字在下、字在上；直式字在下、字在上），進場和離場的方向跟著換。橫式的字用 `|` 標出適合斷行的地方，左右分割時才不會把詞切開
  - 縮圖 `場景模板_場景範例.jpg`（分工樹、錯的 vs 對的、清單卡、驗收蓋章）
- 風格：`glass` 淺色玻璃、`paper` 紙本編排、`dark` 深色。縮圖 `風格三選一_玻璃_紙本_深色.jpg`（由左到右）
- 配樂：`smile` 明亮輕快、`closeup` 穩重有節奏、`clouds` 科技感、`september` 溫和放鬆。都是 Mixkit 免費音樂授權，不用標示作者，腳本自己下載
- 圖示：`stack`、`big` 模板每個重點配一個（`icon`），標題配一個主題圖示（`title_icon`，開場填滿空著的區域，重點往上疊模板結尾再畫一次），沒填的重點只會顯示數字。`scene` 模板只有 `icon`、`actor`、`split`、`number` 場景用得到圖示（`title_icon` 選填，會站在開場主角旁邊）。圖示有六套可以換，spec.json 的 `icon_set` 填套名，**一支片只用一套**，依風格挑（資料和授權在 `references/quick/`，一般流程也可以從這裡拿）：`lucide` 線條（預設，約 2,100 個）、`tabler` 線條（最多，約 4,900 個）、`phosphor` 圓潤線條、`phosphor-duotone` 線條加淡色塊、`phosphor-fill` 實心（各約 1,500 個）、`material` 圓角線條（Google，約 3,500 個）。每套的名稱不同，用 `python3 -I <skill>/scripts/icon_search.py --set <套名> <英文關鍵字>...` 找，例如 `icon_search.py --set phosphor coffee deadline "light bulb"`，一次可以查好幾個字；沒寫 `--set` 就是 Lucide。`draw` 動畫在 `phosphor`、`material` 上會改成由左往右揭開（它們是填色圖形，沒有線條可以畫）。下面是 Lucide 常用的，直接填名字。挑最能代表那個重點的具體物品，不要每個都用抽象的勾勾、箭頭：
  - 人：user、users、user-check、handshake、face-slightly-smiling
  - 文件：file-text、files、clipboard-list、notebook-pen、folder-open
  - 溝通：message-circle、messages-square、mail、megaphone、phone
  - 時間：clock、calendar、timer、hourglass、alarm-clock
  - 檢查：circle-check、list-checks、search、eye、shield-check
  - 問題：circle-question-mark、circle-exclamation-point、triangle-exclamation-point、circle-x、lightbulb
  - AI 與科技：bot、sparkles、cpu、brain、laptop
  - 工作：briefcase、target、flag、rocket、puzzle
  - 流程：arrow-right、git-branch、layers、split、repeat
  - 數據：chart-column、trending-up、calculator、chart-pie、gauge
  - 金錢：wallet、coins、piggy-bank
  - 生活與學習：coffee、house、heart、book-open、graduation-cap
  - 地點：map-pin、globe、building
  - 工具：wrench、settings、pencil、scissors、key
- 圖示動畫（`motion`，每個有圖示的重點和 `title_motion` 都可以選；沒填是 `draw`）：
  - `draw` 線條一筆一筆畫出來，畫完迸出幾道短線：通用，預設
  - `pop` 從小點彈出來、衝過頭再停好：輕快、新點子
  - `drop` 從上方掉下來，落地壓扁再彈回：有份量的事、結果
  - `spin` 旋轉著放大進場：流程、循環、設定
  - `flip` 像翻牌一樣翻過來：換個角度、對照、揭曉
  - `slide` 從左邊快速滑進來：速度、下一步、移動
  - `pulse` 畫出來後像心跳一樣跳兩下：最重要的那一點
  - `wiggle` 畫出來後左右搖晃：提醒、警告、常犯的錯
  - 依重點的意思挑，同一支片最多混用 3 種，看起來才像同一支片；沒有特別理由就用 `draw`
  - 效果改寫自 Motion Prompt #003、#010、#011，已經寫在腳本裡，不必再查目錄
- 音效、鏡頭都由模板決定，不另外挑
- 節奏比一般流程快：元素少，動作和停頓都縮短，結尾停住約 1 秒再淡出

流程（兩關）：
1. **第 1 關**：語言、方向、長度、用途在第 0 關問過，使用者在故事線選了輕量模板時，一起確認那條附上的模板、風格、配樂；想換再看縮圖改選。圖示和動畫不用問，寫進 `spec.json` 一起在第 2 關確認。選擇和理由存成 `01_選擇.md`。輕量模式只存 `01_故事線.md`、`01_選擇.md`、`script.txt`、`spec.json`，不另寫大綱、旁白稿
2. **第 2 關**：寫 `script.txt`（旁白：開場只用一句話帶出主題，第一個重點約 4 秒內出現，超過 4.3 秒時 `quick_build.py` 會提醒，只差一點不必改。cue 可以從「第一，」這類編號開始，重點會在講到編號時就出現；結尾句規則照「各關的做法」的結尾）和 `spec.json`（欄位寫在 `quick_build.py` 開頭的說明），用 `tts_words.py` 產生正式配音，把旁白稿和配音一起給使用者確認。這份配音就是成品用的，不另做試聽
3. **確認後製作**：
   - `python3 -I <skill>/scripts/quick_build.py spec.json`：產生 `index.html`，配好字幕、音效、配樂和配樂音量，約 3 秒
   - 腳本說字太長、重點太多時，改 `spec.json` 的內容（縮短、合併），不要改模板，也不要手改 `index.html`
   - 標題、重點、結尾句可以用 `|` 指定換行，例如 `"AI 分工的|*4 個步驟*"`，避免最後一個字單獨掉到下一行
   - 跑一次 check；字幕的 line_unread 警告是配音速度決定的，可以不處理
   - 每個重點的秒數由配音決定，不套「各關的做法」裡每個重點約 5 秒那條：模板每個畫面只有一個字或一行字，跟著旁白出現，2–3 秒看得完
   - 台詞長度依第 1 關定的片長算：中文約「（片長 − 1.5 秒）× 每秒 3.8–4.5 字」，字數不含標點，英文縮寫每個字母算 1 字（AI 算 2 字）；短句多、標點多時取每秒 3.8 字那一端，例如 25 秒約 90–105 字、30 秒約 110–128 字。輕量模式結尾只停約 1.5 秒，所以字數要比一般流程多一點（2026-11-23 兩次實測：108 字配音 23.9 秒；短句多的 96 字配音 25.0 秒）
   - 配音後片長和需求差 15% 以內，不補台詞重配；差更多就補台詞，重跑配音和 `quick_build.py`
   - 和結尾大字重複的字幕腳本會自動拿掉（以整句為單位，不會留下半句）；配樂音量會自動壓到每段空檔都比配音低 14 dB 以上；量音量的空檔秒數腳本會印出來，直接給 `audio_levels.py`
   - 用腳本印出的截圖秒數 snapshot 一次（直接貼給 `--at`；`scene` 模板每一幕各一張，加上換到結尾那一刻），看過沒問題就 render
   - 驗收照「自檢」第 5 點（抽格、ffprobe、audio_levels），第 3 點的對比和第 6 點的版面量測不用做，模板已經量過

## 依題目選原則

目的：不同題目適合的做法不一樣，同一套規則全開，有的題目會被拖累。2026-11-22 三支示範片各做三個版本比較：觀念片用 5 個重點、一個畫面演到底的版本最好；縮寫口訣片字最有力、細節最多的版本最好；實體操作片開滿導演原則（3D 場景、鏡頭、材質聲）的版本最好。

- 「設計品味與動態」每支都用
- 「導演原則」分兩層：**基本款**每支都用；**進階款**由使用者在第 1 關挑故事線時決定（見「讓使用者選做法」），下表的「導演原則」欄是推薦
- 只開基本款時，鏡頭可以用一兩個簡單的推近、拉遠（例如結尾拉遠看全貌），只是不要求三種鏡頭、招牌時刻和轉折停頓

| 題目類型 | 例子 | 導演原則 | 重點 |
|---|---|---|---|
| 觀念溝通 | 管理觀念、用比喻講道理 | 基本款 | 重點少、一個畫面往上加，比喻要清楚，不加多餘的段落 |
| 字或符號當主角 | 口訣、縮寫、清單、數字 | 基本款 | 讓那個字或符號當畫面主角，用字級和版面構圖 |
| 實體操作、產品、空間 | 組裝、搭建、使用步驟、產品介紹 | 基本款＋進階款 | 鏡頭、材質聲、招牌時刻；真的需要立體時才用 3D（見「3D 與 canvas」） |
| 有角色的故事 | 情境劇、前後對比、客戶故事 | 基本款＋進階款 | 角色的情緒變化、轉折、演出 |

- 落在兩類之間時（例如有角色的觀念片），在第 1 關寫出判斷和理由，基本款、進階款的故事線都列出來讓使用者挑
- 使用者說「照建議直接做」時，由 Claude 判斷，製作前列出採用的類型

## 設計品味與動態

目的：避開一看就知道是 AI 做的長相，讓畫面和動作都從內容長出來。2026-11-22 參考 open-design（GitHub 上的設計工作平台）裡 motion-design 和 taste-skill 的做法，挑出適合影片的部分，用自己的話寫成下面幾條。

設計品味：
1. **先寫一行設計判讀再畫**：「這支片給＿看，要讓人覺得＿，用＿的視覺世界」。「高級感」「有質感」「現代」不算方向，要說得出畫面裡放什麼、視線停在哪裡
2. **一種視覺世界貫穿全片**：例如墨水、摺紙、精密儀器、拼貼、幾何向量，光線、邊緣和質感都照同一套邏輯
3. **顏色**：一個主色，整支片鎖定不換。不用純黑，用帶一點色的深灰。文字和它背後的底色，對比至少 3:1（3 比 1，數字越大越清楚；使用者 2026-11-24 定），照最不利的地方算：光暈中心、圖片上、整塊變淡之後。要讓一塊東西退到後面，用縮小、換成灰色，不要把整塊調成半透明，字會跟著被吃掉
4. **字是畫面的一部分**：用字級、對齊、斷行和留白構圖，不只是把字放上去。中文標題兩行以上，行高 1.3 左右
   - **一眼看得出先看哪裡**：一個畫面只有一個主角，主角至少用兩種手段和別人拉開（大小、粗細、顏色、留白、位置），不要只靠放大
   - 字級分得開才有階層：字幕以外，一個畫面約三種字級，相鄰兩級約差 1.5 倍（open-design 寫 1.25 倍，影片看得遠、停留短，這裡放大，是推算值）；文字大約四塊以內，放不下就分次出現
   - 出場順序就是重要順序。會跳動或上下對齊的數字用 `font-variant-numeric: tabular-nums` 並留好寬度，不然會左右晃
5. **間距要看得出誰跟誰一組**：目的是讓觀眾一眼分出群組，也讓字有呼吸的空間。2026-11-24 使用者指出最近幾支的文字貼著框、框貼著框、標籤壓到視窗
   - 用倍數想，不用固定像素，字大間距就大。參考：單行框的留白上下約 0.4 個字高、左右約 0.8 個字高；多行的卡片約 0.8–1 個字高；同一組的框之間約 0.4–0.5 個字高；不同組之間是組內的 2 倍以上；字幕框和主畫面之間約 1 個字高
   - 同一組的東西用 flex 加 gap 排，不要每一個手算座標，加一項、改一個字就會擠
   - **放不下時減內容或分次出現，不要縮間距**。例如聊天訊息放不下就像真的聊天一樣往上捲、開場只放標題和視窗上半截，等標題離場再升上來
   - 特效的範圍（迸出的短線、陰影、角標）也算進去，不壓到旁邊的字
6. **避開 AI 預設長相**（內容真的需要時例外，但要說得出理由）：紫藍漸層、到處發光、什麼都做成毛玻璃、置中大標下面三張一樣的卡片、米色配黃銅色的「高級」配色、深底配青色霓虹、沒有意義的色塊和波浪、漸層色的字、左邊一條色帶的圓角卡片、拿 emoji 當圖示、每一段上面都放一行小標籤、「Step 1」「01 / 04」這種只有編號的空標籤（改寫成動詞，例如「先拆工作」）、用方塊拼出來的假產品畫面。字型（英文 Inter）和圖示（Lucide）也是大家預設會拿的，能用，但要想過跟內容合不合，圖示有六套可換（見「輕量模式」的圖示）
7. **不編數字**：畫面上的數字要有來源或是使用者給的；只是示意時用看得出是示意的寫法，不要編一個看起來很精準的數字
8. **構圖不重複**：每一幕都同一種排法，觀眾會覺得只是換字。大綱的每一幕寫上排法（例如左文右圖、左右對照、置中大字、滿版一張圖），同一種排法不要連續三幕；左文右圖、右邊一個場景演到底的做法算一幕，它靠右邊的場景變化
9. **數據畫面**：數字要看得出輕重，不只是把數字寫大
   - 配一個能看出大小的圖形；同一個概念的數字變化時，留在同一個位置、同一個圖形上變，不要換一頁
   - 影片停留短，不放圓餅圖、雙軸圖、六格以上的儀表板，格線、刻度、圖例能拿掉就拿掉，直接把名稱寫在圖形旁邊
   - 動畫途中的單位、比例和起點都要正確，長條從 0 開始；意思不能只靠顏色分辨，要有文字或形狀
10. **閃爍**：同一個區域一秒最多閃 3 次，避免讓人不舒服

動態：
1. **先做好一張代表畫面**：靜態畫面不好看，加特效也救不回來
2. **動作分三層，不是每層都要**：主動作講重點；次動作表現重量或因果（標籤跟著到位、陰影落定）；環境動作只在需要時加。安靜和讀字的段落可以完全不動
3. **時間參考**（依距離、重量、情緒調整）：小強調 0.12–0.22 秒；主元素進場 0.35–0.65 秒；形狀變化 0.6–1.2 秒；大揭露或鏡頭移動 0.9–1.8 秒。進場用減速、退場用加速、在畫面上移動用先加速後減速；退場比進場快（例如 0.4 秒進、0.25 秒出）；精密的東西不要彈跳、走直線，可愛或有重量的東西可以回彈、走弧線
   - 同一幕不要每樣都用同一種速度曲線、同一個方向進來；一串東西依序出場，全部在 0.5 秒左右到齊（講到才出現的除外）
   - 一幕分三段：前三成把東西建立起來，中間留時間讓人讀（最多一個很小的環境動作），最後三成收掉或帶到下一幕
   - 字在要被讀的時候不旋轉、不模糊；彩帶、閃光這類慶祝效果一支片最多一次
4. **換場依前後關係選**：形狀相接、跟著一個物件進下一幕、遮罩揭露，或乾淨硬切；不是為了變化而變化。意思也不同：淡入淡出是「接著講」，硬切是「醒一下、轉折」，慢慢溶接是「時間過去」
5. **動靜交替**：最強的變化留給核心觀念，一直維持最高強度會讓每個段落都一樣
6. **做的時候對照**：

| 問題 | 改法 |
|---|---|
| 像投影片 | 讓一個物件貫穿全片、變形到下一幕 |
| 每樣都在搶 | 選定主動作，其他減少或延後 |
| 沒有重量感 | 調整移動時間、加減速、預備和落定 |
| 字讀不完 | 加長停留、加強對比，可以時縮短文字 |
| 看起來很普通 | 加強字體、構圖和跟主題有關的符號 |
| 很忙但沒說什麼 | 拿掉裝飾性的動作，留下講因果的動作 |

## 導演原則

目的：畫面好看只是起點，觀眾記得的是節奏、聲音和鏡頭。2026-11-21 參考 Lemo-Opuscar（GitHub 上的做片 skill）的導演方法，挑出適合短片、又不會多花太多額度的部分，用自己的話寫成下面幾條。判斷一支片時依序看：聲音、節奏、鏡頭、演出，最後才是單張畫面好不好看。

第 1、6 條和第 7 條前半（看得到的動作都有聲音；同時發生的幾個動作可以共用一聲）是**基本款**，每支都用；其他是**進階款**，依「依題目選原則」決定開不開。

1. **故事**：一個主角（可以是一個人、一件東西或一個觀念）、一個目標、一個轉折，結束時和開始時不一樣。前 3 秒就要有事情發生，不要先慢慢出標題。結尾呼應開頭，例如回到開場的畫面但狀態變了。看不懂要解釋的段落直接刪掉
2. **參考作品**：大綱時替這支片挑一部參考（廣告、片頭、動畫、遊戲都可以），寫一行「學它什麼（構圖、節奏、鏡頭語言、配色）、不拿什麼（角色、設計、旋律、特定鏡頭、商標）」。參考只學手法，不照抄
3. **一個招牌時刻**：全片選一個最想讓人記住的動作，放在情緒最高點，例如整個畫面重組、從細節拉遠看到全貌。其他段落讓位給它
4. **鏡頭**：平面動畫也有鏡頭。一支 30 秒的片至少用 3 種不同的鏡頭動作（推近、拉遠、橫移、前後景視差、畫中畫），每個都要說得出理由。換場用同一套和內容有關的手法（左文右圖、右邊一個場景演到底時，換場指左欄文字的更換），例如卡片翻面帶到下一幕、線條延伸成下一個畫面；不要每次都淡入淡出或直接硬切（結尾的淡出例外）。關鍵時刻主體至少佔畫面高度的三分之一
5. **節奏**：快慢要交替，全片要有一次明顯的加速或放慢，並留一口氣（主體留在畫面上、動作停住）。轉折前留 0.5–1 秒的停頓，停頓後的第一個音效要是全片最重要的一聲。**停頓指聲音的停頓**（配音、音樂、音效收住），畫面要留著主體，不能因此變成空白畫面（2026-11-22 示範 1 的導演版把停頓做成近乎空白的畫面）。轉折和招牌時刻不在同一處時：停頓放在轉折前，招牌時刻放在情緒最高點；兩者只差幾秒時，只留一次停頓，放在招牌時刻前。整支片同一個速度就是失敗。聲音停頓的做法（進階款才用，基本款只有結尾停住）：`tts_words.py` 不能插停頓，要在 `voice.mp3` 的停頓點用 ffmpeg 切成前後兩段、中間接一段靜音，再把 `words.json` 那一點之後的時間全部加上停頓秒數；音樂那一段用 ffmpeg 的 volume 濾鏡在 `bgm.mp3` 上壓低（例如 `volume=0.2:enable='between(t,12.3,13.0)'`）
6. **讓人讀得完**：想快就減少每個畫面的字，不要在觀眾讀完前換掉。兩個標準：
   - check 的 line_unread（約 0.5 秒＋每個詞 0.3 秒）一定要過，它會擋
   - 沒有旁白帶到的標題和說明文字，另外用「字數 ÷ 4.5 ＋ 1.5」秒（英文「字母數 ÷ 15 ＋ 1.5」秒）當目標。跟著配音出現的字幕，和刻意快翻的數字（例如計數器）不套這條
7. **聲音**：看得到的動作都要有聲音，而且聲音要配材質（紙、金屬、玻璃聽起來不一樣）。至少一次用聲音帶換場：下一幕的聲音提早進來，或上一幕的聲音延續過剪接點
8. **演出**：重要的動作都要有預備、動作、餘韻三段（可以搭 Motion Prompt 的 #121 Anticipation、#122 Follow-through），不要只是平移滑過去

## 人物

目的：片中需要人物時，用現成又能演戲的人物，不要自己畫簡筆線稿。2026-11-23 使用者指出自己畫的線稿人物看起來很幼稚；微軟 Fluent Emoji 因為手腳不能動被否決；Open Peeps 的手繪風格使用者喜歡。

- **什麼時候用**：一般流程裡有人物的畫面，優先用 Open Peeps；輕量模式有固定主角，不用
- **怎麼組**：
  1. 先看 `references/peeps/` 的一覽圖挑零件：`姿勢_全身站姿_一覽.jpg`（26 種）、`姿勢_半身_一覽.jpg`（28 種）、`姿勢_坐姿_一覽.jpg`（11 種）、`表情_一覽.jpg`（33 種）、`髮型_一覽.jpg`（51 種）；鬍子、配件的名稱用 `peep.py list` 看
  2. `python3 -I <skill>/scripts/peep.py make <角色代號> --pose <姿勢,...> --face <表情,...> --hair <髮型> -o <檔名>`，把產生的 `<svg>` 貼進 `index.html`。用法和選項寫在腳本開頭
  3. 線條色 `--ink` 跟著本片風格調。填色 `--fill` 會同時染到衣服、皮膚和淺色頭髮，只能用接近白的顏色（例如 #ffffff、#fbefe0），不能拿來區分角色：2026-11-23 試做用淺藍填色，同事變成藍皮膚；用淺米色，主管的灰髮變成金髮
  4. 同一支片有好幾個角色時，用髮型、眼鏡或鬍子、衣服明暗（姿勢名稱結尾 WB 上白下黑、BW 上黑下白）分開
  5. **所有人物都面向畫面右邊**：放在右邊、要面向左邊的角色，在 `<svg>` 外面包一層只負責翻轉的 div，加 `transform: scaleX(-1)`；要讓人物走動、晃動時，GSAP 動再外面一層，不要動這層翻轉的 div（被 GSAP 動到的元素不能另外寫 CSS transform）。翻過來以後，轉頭的角度正負也要相反
  6. **半身姿勢的下緣是一刀切齊的身體**：不要讓切口直接露在畫面上，用桌面、櫃檯、畫面邊緣或對話框擋住
- **怎麼動**（2026-11-23 示範和試做都用過）：
  1. **換表情**：最主要的演法，例如冷靜換成擔心再換成解說。直接切換，不要淡入淡出
     - 開心的表情只用這 6 種（2026-11-23 使用者看過全部開心類表情後選定），沒有特別理由就用 `Smile`：
       - `Smile` 微笑：預設
       - `Calm` 瞇眼微笑：滿足、事情解決了
       - `EatingHappy` 鼓著臉頰開心：滿意、得意
       - `SmileLol` 笑到流淚：真的很好笑
       - `LoveGrin` 愛心眼：非常喜歡
       - `SmileBig` 露齒笑：興奮。使用者說過它不太像大笑，少用
     - 其他開心類表情（`SmileNM`、`CalmNM`、`Cute`、`Cheeky`、`CheersNM`、`SmileTeeth`、`LoveGrinTeeth`）不用
  2. **頭部動作**：轉頭、歪頭、點頭，用 `svgOrigin: "410 460"`（脖子的位置）
  3. **走路**：用走路姿勢（`Walking` 開頭）整個人橫移，加上每步一次的上下輕晃和小角度前傾，停下時換成站姿並落地輕壓一下
  4. **換姿勢**：直接切換，同時整個人輕輕放大再回來，像定格動畫
  5. 眨眼：換成 `Calm`（瞇眼笑）約 0.12 秒再換回來；`EyesClosed` 看起來像在生氣，不拿來眨眼
- **限制與規則**：
  1. **每個姿勢本來是不同的人**：身材、褲子、鞋子都不一樣，同一個角色換姿勢會像換了一個人。名稱只差結尾 BW、WB 的是同一個人換衣服顏色（例如 `RestingBW`、`RestingWB`），一覽圖上也看得出哪些是同一個人
  2. 所以同一個角色以換表情、頭部動作為主，姿勢最多一兩種；要做不同動作時，交給不同角色演
  3. 同一個角色的姿勢要同一類（全身站姿、半身、坐姿擇一），腳本會擋
  4. 手腳不能各自轉動，也沒有游泳、攀爬、滑雪、跑步這類動作；沒有現成姿勢的動作，改用道具、旁邊的圖解或換個拍法，不要自己畫簡筆人
- **授權**：插圖 CC0（Pablo Stanley），零件轉自 react-peeps（MIT），詳見 `references/peeps/LICENSE.md`。片中不必標示，腳本會在 HTML 註解寫上來源

## 語言與方向

### 版面

| | 直式 1080×1920 | 橫式 1920×1080 |
|---|---|---|
| 安全範圍 | 垂直 288–1248；水平 y<840 時 120–888，y≥840 時 120–780（TikTok、Reels、Shorts 三者的交集） | 中央 80%：x 192–1728、y 108–972（CLI 的 title-safe） |
| 構圖中心線 | x=450（右下有平台按鈕列，不是 540） | x=960 |
| 標題 | top 約 312，中文 96px、英文 84px | 可以靠左（例如 left 240、top 140），中文 84px、英文 76px |
| 主畫面 | 底部停在 1100 左右 | y 約 250–800，左右兩半都要有內容（見下方「橫式構圖」） |
| 字幕 | left 120、寬 660、top 1152；中文 46px、英文 42px；底線不能超過 1248 | left 360、寬 1200、top 850；48px；底線不能超過 972 |
| 字幕每組上限 | 中文 12、英文 28 個字元 | 中文 16、英文 42 個字元 |

- 安全範圍的數字取自 HyperFrames CLI 原始碼，check 會照這些數字報 outside_safe_zone
- check 會在動畫進行中取樣：退場往上移、鏡頭橫移時，元素經過安全範圍外也會被報。退場改用淡出或小位移；刻意的鏡頭橫移在移動的容器加 `data-layout-allow-safe-zone`
- 鏡頭推近時，把縮放原點放在標題附近（直式範本的 `#world` 有寫法），標題才不會被推出安全範圍；橫式推近後，主畫面底部仍要停在 830 以上，不要壓到字幕（字幕上緣 850）
- 直式片如果不發到短影音平台，可以改回置中
- 使用者會在意字幕壓到主畫面
- 字幕一律一行；中文的上限用「視覺寬度」算，英文字母約半個中文字（`make_captions.py` 已處理）

### 橫式構圖

目的：橫式畫面是由左往右讀，左右的空間要拿來講事情。直式的習慣是把標題、主畫面、字幕由上往下疊成中間一欄，搬到橫式會留下左右兩大片空白（2026-11-17 使用者指出：重心過度集中在中間）。

原則：
1. 對照、前後差異、流程步驟改成左右並排，不要上下疊
2. 主畫面要用到大部分的可用寬度；只有中間一欄是直式的做法
3. 常見的構圖有三種，可以參考、混用，也可以不照：
   - **左文右圖**：左邊放標題和重點句，右邊放圖
   - **左右對照**：同一個畫面裡左右擺兩種狀況，例如左邊被文件淹沒的 AI、右邊爬不動的進度和一直跳出的錯誤
   - **橫向流程**：流程或分工樹由左往右展開，例如左邊主管 agent，往右分成三個 agent，各接一張工作卡
4. 圖形可以比直式大：右邊有空間時，加上標籤、狀態、勾選等資訊，不要只是把同一張圖放大
5. 字幕照舊放底部置中，主畫面的底部要停在字幕上方

範例：`templates/example_landscape_en.html`（左右對照＋橫向流程）。用 `scripts/measure_span.py` 量的結果，主畫面寬度從舊版的可用範圍 24–54% 提高到 95%，左右兩半的內容量接近。

### 3D 與 canvas

目的：3D 很吸睛，但時間和費用大約是平面的兩倍（2026-11-22 搭帳篷片：3D 版約 65 分鐘、US$9–11，平面版 24–31 分鐘、US$4.4–5.2）。

1. 只有內容真的需要立體空間時才用，例如組裝、搭建、產品外觀。這類題目在第 3 關讓使用者看圖決定：三張風格圖兩張平面（畫法不同）、一張 3D，各標大約要等多久（進階款約 25–30 分鐘、加 3D 約 1 小時），不需要立體的題目不提 3D。多數情況用自己畫的立體投影（SVG 或 canvas 畫等角圖、簡單透視）就夠，也比較快
2. 要用 three.js 這類逐格繪製的 3D 時，照這個寫法，否則截圖和輸出會卡在 60 秒載入逾時（`--timeout` 管不到）：
   - 3D 的狀態另外用一條**不註冊**的 GSAP 時間軸（`gsap.timeline({ paused: true })`，不放進 `window.__timelines`）
   - 監聽 `hf-seek` 事件，拿 `e.detail.time` 把那條時間軸跳到同一秒，再畫一格
   - 3D 場景很重，等頁面載入後再初始化，並用 `window.__hf.buildReady.<名稱> = new Promise(...)` 告訴 HyperFrames 等它，初始化完成才 resolve
   - three.js 從 CDN 載入，輸出時要有網路
3. 3D 片的截圖每次要 2–5 分鐘：3D 的風格圖只做一張，截圖秒數一次給齊
4. `measure_span.py` 遇到滿版 3D 一律量出 115–125%，不用它，直接看畫面

### Windows 中文編碼（避免亂碼）

- 本 skill 的腳本都用 UTF-8 讀寫檔案，主控台輸出也強制 UTF-8
- **不要用 `>` 把有中文的輸出存成檔案**：Windows 會改用 cp950 或 UTF-16 存檔，讀回來就變亂碼（2026-11-17 同事的字幕亂碼就是這樣來的）。要存檔的腳本都有輸出檔參數，例如 `make_captions.py` 直接寫 `captions.json`
- `script.txt`、`index.html` 這類檔案用 Claude 的寫檔工具寫（UTF-8），不要用 PowerShell 的 `echo` 或 `Out-File` 寫
- HTML 開頭要有 `<meta charset="UTF-8" />`

### 字型

- **中文片用思源黑體**（Google 的名字叫 Noto Sans TC，開放字型授權、可商用；使用者 2026-11-24 指定），英文和數字也用它。Mac、Windows、雲端做出來都一樣，粗細 100–900 都有：
  1. 把 `references/fonts/NotoSansTC.ttf` 複製到影片資料夾的 `assets/fonts/`（風格圖的子資料夾也要各放一份）
  2. CSS 寫 `@font-face { font-family: "TC"; src: url("assets/fonts/NotoSansTC.ttf"); font-weight: 100 900; ascent-override: 108%; descent-override: 32%; }`，然後 `font-family: "TC", sans-serif`
  - 不要只寫字型名稱 "Noto Sans TC"：HyperFrames 自動抓的那一份推測只有英數（每個檔 18 KB），中文會退回系統字型
  - `#root` 寫 `font-weight: 500`（沒寫會變成 400，比較細），標題和重點 600
  - `ascent-override`、`descent-override` 兩個值要照抄：思源黑體原本的字會比框的正中間低約 0.06 個字高，加了才會置中（2026-11-24 量字幕框：沒加時上 27、下 21 像素，加了要一樣）
- **純英文片**：直接寫 `font-family: "Inter", sans-serif`，Inter 是 HyperFrames 內建字型，Mac、Windows、雲端渲染都一樣
- 字級適度、粗體少用（只給關鍵字和小標）

### 配音

- **中文**：`zh-TW-HsiaoChenNeural`（曉臻），語速 +10%；另一個女聲是 `zh-TW-HsiaoYuNeural`（曉雨）。男聲 `zh-TW-YunJheNeural` 在 edge-tts 上會失敗
- **英文**：`en-US-AndrewNeural`（男聲），語速 +0%。也試過能用的：`en-US-AvaNeural`（女聲，稍慢）、`en-US-EmmaNeural`（女聲，稍快）
- 指令：`python -I scripts/tts_words.py script.txt voice.mp3 words.json <聲音> <語速>`

### 字幕斷句（`scripts/make_captions.py`）

- 用法：`python -I scripts/make_captions.py script.txt words.json <zh|en> <v|h> captions.json [總秒數]`（直接寫檔，不要用 `>` 轉存）
- 句號、冒號、分號一定斷開；一句裡優先在逗號處分組，分成最少組，而且最長那組盡量短
- 逗號之間的一段本身就太長時，才在詞與詞之間平均切，不會留下單獨一個字
- 字幕文字取台詞原文：中文逗號換成空格、句尾標點拿掉；英文保留句中逗號

### 風格

- 沒有預設風格。第 3 關由 Claude 依內容設計三種（畫法各不同），使用者指定風格就照他的；要「公司風格」時參考 `references/design-glass.md`（淺色玻璃風）
- 設計原則：風格從內容來（主題、觀眾、情緒），字要讀得清楚、顏色對比要夠，一個畫面只有一個重點。避開「AI 感」很重的預設長相：紫藍漸層、到處發光、每支片都一樣

## GSAP 與 check 的坑

- 不能對 `letterSpacing` 做動畫，check 會報錯；改用位移加淡入
- 被 GSAP 動到的元素不能另外寫 CSS transform
- 重複動畫要寫有限次數的 repeat，不能寫 `repeat:-1`
- 每個音效 `<audio>` 都要寫 `data-duration`（長度看音效庫 `~/.claude/skills/media-use/audio/assets/sfx/manifest.json`，或用 ffprobe 量；複製到專案的音效沒有附這個檔），否則會被當成一路播到片尾
- 用 `npx hyperframes check --json 2>&1 | python3 scripts/check_summary.py` 看結果（Windows 把 `python3` 換成 `python`），要做到 ok，而且沒有 outside_safe_zone
- **對比不能只看 check**：它不會算整塊變淡（2026-11-24 實測畫面只有 2.49 仍判通過），白字疊在 SVG 圖形上又會拿錯底色。對比用 `scripts/contrast_px.py` 從實際畫面量（見「自檢」），check 報的 contrast 問題拿它複核，量出來有 3 以上就不用改
- 背景柔光故意超出畫面時會出現 container_overflow 警告，可以忽略
- SVG 元素用 GSAP 做 `scaleY`、`transformOrigin`、`svgOrigin` 時常會錯位（例如水位、水柱長錯方向）；改成直接動畫屬性，例如 `attr: { y, height }`
- **CSS 寫在 `index.html` 的 `<style>` 裡**，不要另開 css 檔；專案根目錄只能有一個帶 `data-composition-id` 的 HTML，風格圖放在 `03_風格/` 子資料夾，否則會報 multiple_root_compositions
- **第 0 格不能只有底色**（first_frame_empty）：第 0 格是平台和網頁的縮圖，開場第一格就要有標題或主體
- **進場用 fromTo 寫**，開始前會停在起始值；在第 0 秒用 `tl.set` 隱藏不會生效。同一個元素有兩段 fromTo 時，後面那段加 `immediateRender: false`，否則它的起始值會蓋掉前一段
- **被遮罩藏住的字、上下疊兩層再切換透明度的字**會被報 text_occluded：藏住的時候透明度設 0，或加 `data-layout-allow-occlusion`
- `data-layout-ignore` 會讓 check 以為畫面停太久而誤報；connector_orphan 也常誤判。看截圖確認沒問題就不用改
- 拉遠的結尾、或把元素縮成小圖示時，會報 text_below_floor（字跟著縮小）。縮小的字本來就不是給人讀的、或看截圖讀得清楚，就不用改
- 輸出中途失敗（例如 detached Frame、瀏覽器當掉）：加 `--workers 1` 重跑。同時有別的 hyperframes 預覽或輸出在跑時特別容易發生
- Mac 的終端機（zsh）不會把變數拆成多個參數：例如 `enc="-c:v libx264 -crf 20"` 再寫 `ffmpeg ... $enc`，ffmpeg 會把整串當成一個參數而報錯。參數直接寫出來，或改用陣列
- 在 heredoc 或迴圈裡跑 ffmpeg 要加 `-nostdin`，否則它會讀走後面還沒跑的指令，那些指令不會執行、也不會報錯
- snapshot 除了指定的秒數，會多截一張片尾；圖存在 `.hyperframes/artifacts/snapshots/<編號>/`，看 `contact-sheet.jpg` 就好

## 聲音

- **配音**：聲音和語速見上方「語言與方向」。Mac 內建的 `say` 聲音被評為太機械，不建議用
- **音樂：依內容挑，由 Claude 自己找、自己下載**
  1. 從大綱判斷情緒和節奏，換成英文關鍵字。常見對應：
     - 輕快解說、工作技巧：happy、corporate（Mixkit 沒有 upbeat 標籤）
     - 溫暖故事、人物：piano、warm（Mixkit 的 acoustic 幾乎沒有 45 秒以上的曲子）
     - 科技、產品介紹：electronic、tech、ambient
     - 正式報告、成果：cinematic、inspiring
     - 輕鬆生活：chill（Mixkit 的 lofi 沒有 35 秒以上的曲子）
  2. 用 `scripts/find_music.py` 搜尋，長度至少要蓋過整支片（例如 30 秒片找 35 秒以上）：
     - `python -I scripts/find_music.py mixkit <標籤> <最短秒數>`：Mixkit，免費可商用、不用標示作者（不能把原始音檔再散布出去）
     - `python -I scripts/find_music.py openverse "<關鍵字>" <最短秒數>`：Openverse，彙整多個創用 CC 音樂庫，會附上要貼的標示文字。常回 403、500，連不上時腳本會停下來提示，改用 Mixkit
     - Mixkit 只抓得到標籤頁、看不到單曲的曲風分類：同一個標籤裡可能混著兒歌、遊戲音樂（例如 Owies Ukulele 其實是兒歌），挑曲時看曲名，有疑慮就換一首
     - 想要古典樂時，到 Wikimedia Commons 找公共領域或 CC 授權的錄音（可以用 API 查授權：`action=query&prop=imageinfo&iiprop=url|size|extmetadata`）
     - 這幾個都找不到合適的，可以自己上網找別的免費可商用來源，但要確認授權，而且 Claude 能直接下載
  3. 在第 3 關挑 2–3 首給使用者：推薦理由、來源、授權、要不要標示作者，並剪一段 15 秒左右的試聽檔
  4. Claude 聽不到聲音，只能依標籤、曲名和長度挑。沒有人試聽時（「直接做」或使用者沒空），交件時寫明「配樂沒有試聽過」
  5. 使用者選好後，把那一首下載到 `assets/bgm/source/`（例如 `curl -L -o assets/bgm/source/<曲名>.mp3 <音檔網址>`；Windows 10 以上也有 curl），之後試不同起點都從這份剪，不要每次重新下載，用 `python -I scripts/prep_music.py <原曲> assets/bgm/bgm.mp3 <影片秒數> [起點秒數]` 剪成影片長度。原曲比影片短 5% 以內時腳本會自動放慢補足並說明，短更多會停下來，這時換一首較長的
- **授權**：
  - 可以用：公共領域、CC0、Mixkit 免費音樂授權
  - CC BY（要標示作者）在沒有更好的選擇時可以用。選之前先看它要求怎麼標示，會不會傷畫面：要放在片中的文字有多少、最小字級、能不能只放在說明欄或片尾。會傷畫面就換一首
  - CC BY-SA 盡量避開：「相同方式分享」的條款會延伸到整支影片，真的要用時另外先告訴使用者
  - 不可以用：不可商用（NC）、禁止改作（ND，剪進影片就算改作）
  - 古典樂的曲子沒有版權，但**錄音另外有版權**，要看錄音本身的授權；公共領域的老錄音常是單聲道、低位元率，音質差
  - 下載前要看曲目頁面的標籤和說明，確認是不是改編版（曾經遇過標題是莫札特、其實是電吉他重金屬改編）
- **混音**：
  - 用 loudnorm 正規化到 -20 LUFS，結尾 2 秒淡出（`prep_music.py` 會做）
  - `data-volume` 每首都要算，不要套固定值：`python -I scripts/music_volume.py assets/audio/voice.mp3 assets/audio/words.json assets/bgm/bgm.mp3`（路徑照專案實際位置）。2026-11-18 升降桌片的 Digital Clouds 算出 0.21，舊的固定值 0.45 會讓空檔的音樂只比配音低約 9 dB
  - 目標是配音空檔的音樂比配音低 14–19 dB；低到 -40 dB 就幾乎聽不到了。`music_volume.py` 依平均值算，個別空檔超出範圍時會逐一列出：差太多（音樂太小聲）多半是曲子那段比較輕，可以接受；差太少（音樂太大聲）要換起點或降一點音量。換起點的做法：用 `prep_music.py` 從幾個不同秒數各剪一份，各跑一次 `music_volume.py`，選沒有被列出「太大聲」的那個
  - 輸出後用 `python -I scripts/audio_levels.py <影片> words.json <空檔起點:長度>...` 複查。要給 words.json：沒給時配音段固定量 5–7 秒，這兩秒裡有停頓就會量得太小聲（升降桌片少算約 3 dB，誤以為音樂太大聲而多重新輸出一次）。挑空檔要避開音效的時間點（長音效的尾巴會延續好幾秒，也要避開），而且從前一個字的結束時間再往後 0.1 秒起算（words.json 的字尾比實際聲音早約 0.05–0.1 秒，太早起算會把字尾量進去，誤判音樂太大聲）。旁白和音效重疊時，腳本印的「配音段」會把音效一起量進去而偏大聲（2026-11-23 雪崩片多算約 4 dB，看起來像音樂太小聲）；這時改用 ffmpeg 的 volumedetect 量一段沒有音效的旁白當基準，再和空檔比
- **音效**：初稿就配上。從音效庫複製到專案的 `assets/sfx/`，音量 0.3–0.5，在換場、元素出現、強調的地方用，數量依畫面需要，不必湊數，也不要多到蓋過配音。0.3–0.5 只適用本身不大聲的音效：impact-bass-1 平均約 -4 dB，用 0.45 會比旁白大聲約 7 dB（2026-11-23 雪崩片因此多輸出一次）。和旁白重疊的音效，輸出前先用 volumedetect 量音效檔，算出乘上音量後比旁白低幾 dB，低音撞擊類用 0.15–0.2，或移到旁白的空檔。開了導演原則進階款時，聲音要配材質；音效庫沒有紙張、寫字這類材質聲，先用最接近的（例如紙張用 click-soft、倒水用 whoosh），交件時說明

## 自檢

1. 跑 check（上面的指令）。動畫整份寫完再跑，修完一批再跑一次確認；不要每改一處就跑一次（2026-11-22 量測：一支片 check 加截圖合計 4–7 分鐘）
2. `npx hyperframes snapshot --at <各幕關鍵秒數>`，秒數一次給齊（例如 `--at 2,7,12,18,24`），用 Read 看那一張 contact sheet：文字有沒有擠、重疊、超出畫面，有沒有壓到字幕。修改後只截改到的那幾秒，不要整排重截，也不要一秒一秒分開截
3. 量對比（輕量模板已經量過，不用做）：`<edge-tts 環境的 python> -I scripts/contrast_px.py <影片資料夾> <各幕停好的秒數>`，每一塊字都要 3 以上。秒數挑東西都進場、沒有在淡入淡出的時候；6–8 個時間點約 40 秒
4. 輸出：`npx hyperframes render --quality delivery -o renders/<名稱>_vN.mp4`，一支 30 秒的片大約要 3 分鐘
5. **從成品驗收**：用 `scripts/frame_sheet.py` 抽 8 格看（依片長平均取格，直式、橫式都能用），另外抽最後 3 秒看結尾有沒有收、有沒有淡出，看第 0 格是不是有標題或主體（網頁和平台的縮圖），用 ffprobe 確認長度、解析度（1080×1920 或 1920×1080）、有音軌，再跑 `scripts/audio_levels.py`（記得給 words.json）
6. **版面有沒有用到這個方向的空間**（只有橫式要量，直式跳過）：每一幕挑一個畫面都進場後的秒數，跑 `<edge-tts 環境的 python> -I scripts/measure_span.py renders/<檔名>.mp4 <秒數>...`（要用裝了 numpy、pillow 的 edge-tts 環境）。橫式的主畫面寬度要到可用範圍的 70% 以上，而且左右兩半都有內容；不到就回頭照「橫式構圖」重排。數字只是提醒，最後仍要看畫面。背景是滿版格線、紋理、淡色漸層或滿版 3D 時，整個畫面都會被算成有內容，量出來 100–125%，這時不用這個腳本，直接看畫面判斷；一般畫面也可能多量幾 %。刻意置中的結尾版面不必到 70%
7. **常見失誤逐項看**：主體太小或貼在畫面邊緣、**框貼框、字貼框、標籤或特效壓到別的東西**（contact sheet 縮太小看不準，挑元素最多的那一幕看原尺寸）、字幕壓到主體、動作快到看不懂、換場時出現空白畫面。只有招牌時刻那一個動作用 0.2 秒一格抽格放大看（沒開招牌時刻時，挑最重要那一幕的主動作）；成品跑 `ffmpeg -i <影片> -vf blackdetect=d=0.1 -an -f null -` 確認沒有黑畫面
8. **只修一輪**：自檢找到的問題一次修完、再檢查一次就交件；第二次檢查才發現的大問題，交件時用一句話告訴使用者
9. 回報時要寫出沒有驗證到的部分。例如音效只量了音量、沒有實際聽，就要明說

## 省成本

- 一次要做多支片時，每一支交給一個分身（fork），主線只負責整理規格、統一驗收和傳檔
- 主線對話越長，每一步都要重讀越多快取；閒置超過 1 小時後快取會過期，再呼叫一次要整段重寫
- 只要產生音檔時，可以請使用者自己在終端機跑 edge-tts，不必經過 Claude
- 動態效果用 `motion_catalog.py` 只查需要的幾行：一次搜尋約 1 KB、一個效果的規格約 1.5 KB；整份目錄約 60 KB，不要整份讀進來
- 參考數據（2026-11-22，九支示範片，照建議直接做、含完整自檢）：一支 30 秒片約 17–30 分鐘、US$3–5（Opus 5.5 API 價換算）；3D 片約兩倍。本檔的金額都只給維護 skill 的人參考，不告訴使用者，使用者只看「讓使用者選做法」的等待時間。時間大致是：讀 skill 與規劃約 4 分鐘（多半是模型在想）、寫第一版約 2 分鐘、每次 check 約 1.2 分鐘、輸出約 3 分鐘
